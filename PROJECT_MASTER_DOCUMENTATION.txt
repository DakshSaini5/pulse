==================================================
1. EXECUTIVE SUMMARY
==================================================
Project Name: Pulse
One-line Description: A secure, HIPAA-compliant, AI-powered medical platform for health record digitization, analysis, and healthcare navigation.

Detailed Overview:
Pulse is an end-to-end full-stack web and hybrid mobile application designed to modernize patient-doctor interactions and personal health record management. It leverages advanced OCR (Optical Character Recognition) via Tesseract.js and LLM analysis via Pulse AI (Google Generative AI) to parse complex, handwritten, or digital medical reports and prescriptions into structured, understandable data. The system features a dual-interface approach: a comprehensive web application for desktop users and a native-like mobile experience via Capacitor.

Purpose of the Project:
To democratize medical data comprehension by translating complex medical jargon, dosages, and test results into plain English, while providing a secure centralized vault for personal health records.

Problem Being Solved:
Patients often leave clinics confused about their prescriptions, dosages, and the implications of their lab reports. Medical documents are frequently lost, misread, or poorly understood, leading to medication non-adherence and health risks.

Target Audience:
- Patients managing chronic conditions or multiple medications.
- Elderly users requiring simplified dosage instructions.
- Caregivers managing health records for family members.
- General users seeking an intuitive platform for medical document storage and AI health assistance.

Industry/Niche:
HealthTech / MedTech / Personal Health Information Management.

Market Need:
With the rapid digitization of healthcare, there is a critical need for patient-facing tools that bridge the knowledge gap between clinical terminology and patient health literacy.

Expected Impact:
Improved medication adherence, reduced adverse drug interactions, better patient health literacy, and a streamlined approach to managing personal and family health data.

2. PROJECT VISION
==================================================
Why was this project created?
Pulse was created to empower patients to take control of their healthcare journey. The founders recognized the anxiety and confusion associated with medical tests and illegible prescriptions.

What problem does it solve?
It solves the "information asymmetry" in healthcare. Doctors have limited time to explain every nuance of a lab report or prescription; Pulse acts as a 24/7 AI-powered medical assistant to fill this gap safely.

What gap in the market does it fill?
While Electronic Health Records (EHR) exist for hospitals, few patient-centric applications successfully combine secure document storage with real-time AI comprehension, OCR extraction, and local hospital discovery.

Long-term vision:
To evolve Pulse into a proactive health-monitoring ecosystem that integrates with wearable devices, telemedicine providers, and digital pharmacy fulfillment centers.

Future scalability potential:
The architecture is built on scalable cloud primitives (Supabase PostgreSQL, Vercel, Railway). The microservices-oriented backend allows scaling the intensive AI and OCR processing independently from the core CRUD operations.

Purpose: Master record for lab reports.

9. API DOCUMENTATION
==================================================
Method: POST | Route: /api/auth/login
Purpose: Authenticate user.
Auth Required: No
Payload: { email, password }
Response: { token, user: { id, email, name, role } }

Method: POST | Route: /api/prescriptions/upload
Purpose: Upload file and run initial OCR.
Auth Required: Yes (JWT)
Payload: FormData (file)
Response: Prescription object with OCR raw text.

Method: POST | Route: /api/prescriptions/:id/verify
Purpose: Send OCR/User text to Pulse AI for structuring.
Auth Required: Yes (JWT)
Payload: { rawText, medicines[] }
Response: Updated Prescription with detailed Analysis records.

Method: GET | Route: /api/admin/stats
Purpose: Fetch platform metrics.
Auth Required: Yes (JWT + Admin Role)
Response: { usersCount, ocrCount, aiCost, ... }

12. DATABASE TO FRONTEND CONNECTION ANALYSIS
==================================================
Example: Uploading a Prescription
1. Frontend `PrescriptionCenter.tsx` creates FormData.
2. Axios POSTs to `/api/prescriptions/upload`.
3. Backend uploads image to Cloudinary -> gets URL.
4. Backend runs Tesseract.js OCR -> gets Raw Text.
5. Backend Prisma creates `Prescription` and `OCRResult` records in PostgreSQL.
6. Backend responds with JSON.
7. Frontend state updates, rendering the Dual-Pane editor.

14. PERFORMANCE ANALYSIS
==================================================
Bottlenecks Identified:
- OCR Processing: Tesseract.js running on the Node thread can block the event loop under heavy load.
- AI Latency: Google Generative AI streaming takes 2-4 seconds.
Improvements:
- Move OCR tasks to a dedicated microservice or a Redis/BullMQ worker queue.
- Implement lazy loading (React.lazy) for heavy frontend components like the Admin Dashboard charts.
